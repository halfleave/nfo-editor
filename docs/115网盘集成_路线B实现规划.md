# 115 网盘集成 · 路线 B 实现规划（P1/P2）

基于调研结论，后端采用路线 B：**纯前端 + JS 透明代理**，复用现有 `nfo-magnet-proxy-vercel` 仓库，不引入 Python/p115client。本文件为开发前范围对齐，确认后进入编码。

## 安全红线（继承自 v1 方案，路线 B 同样适用）

1. 115 cookie 绝不进 GitHub、绝不存 Vercel 环境变量、代理不记录任何日志。
2. 代理加 `X-Proxy-Token` 共享密钥（前端与代理约定），仅允许我们的前端调用，防止代理被滥用当公开 115 代理。
3. 代理只做透明转发（加 CORS 头 + 透传 cookie 头），**不解析、不存储** 115 响应体里的任何业务数据。
4. cookie 仅存手机 IndexedDB（前端持有），与 v1 一致。

## P1：115 透明代理（后端/路由层，Node）

改动文件：`nfo-magnet-proxy-vercel-main/api/index.js`（现有 Vercel Node 函数，与磁力/字幕代理同源）

新增一个 route `/api/115/proxy`：

- 请求：`GET|POST /api/115/proxy?url=<encodeURIComponent 后的 115 完整 URL>`
- 校验：
  - `X-Proxy-Token` 头必须等于约定的共享密钥，否则 403
  - 解析 `url` 参数，hostname 必须在白名单内，否则 403
  - 白名单：`qrcodeapi.115.com`、`passportapi.115.com`、`webapi.115.com`、`clouddownload.115.com`、`upload.115.com`、`115.com`
- 转发：用 `new Request(targetUrl, {method, headers: 透传原请求头含 Cookie, body})` 转发；115 响应原样返回，并补 `Access-Control-Allow-Origin` 为前端源（或 `*` + 凭据模式配 `*` 需前端 `credentials:include` 配合，建议用具体源）。
- 不读、不改、不存响应体。
- 部署：`vercel --prod`（需你 Vercel 授权，本环境无 CLI）。

> 注：现有代理已处理 bt4g 中文 GBK 回退，115 代理独立 route，互不干扰。

### P2.3 扫码登录流程（移植 115-fetch-cookie/index.html 逻辑）

1. 点「扫码登录」→ `GET /api/115/proxy?url=qrcodeapi.115.com/api/1.0/web/1.0/token/` → 取 `data.qrcode` + `data.uid/time/sign`。
2. 用 qrcodejs 库渲染二维码（需引入：放 `src/qrcode.min.js` 由 `nfo-editor-ios.html` 引用，或内联）。
3. 轮询 `GET /api/115/proxy?url=qrcodeapi.115.com/get/status/?{uid,time,sign}`，每 1.5~2s：
   - 0 等待 / 1 已扫待确认 / 2 已登录 / -1 过期（重新生成）/ -2 取消。
4. status=2 → `POST /api/115/proxy?url=passportapi.115.com/app/1.0/web/1.0/login/qrcode/`，body `{app:'web', account:uid}`，带 Cookie 透传 → 取 `data.cookie` 对象。
5. 拼成 `UID=..; CID=..; SEID=..; KID=..` 字符串 → 自动填入输入框 + 存 IndexedDB（key 如 `state.c115Cookie`）+ 调连通性自检。

### P2.4 磁力 → 115 云下载（离线下载）

- 搜索结果/详情页「离线下载」按钮 → 取磁力链接 → `POST /api/115/proxy?url=clouddownload.115.com/lixianssp/?ac=add_task_url`，body `{url:magnet, wp_path_id: <用户选定目录 cid>}`（cookie 透传）。
- 目录选择：先用 `webapi.115.com/files?cid=0` 拉根目录，让用户选目标文件夹（默认「云下载」目录 cid，P0 实测为 3311283881428122938），存偏好。
- 返回成功 toast；失败保留错误文案。
